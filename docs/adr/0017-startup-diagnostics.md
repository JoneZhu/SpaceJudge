# ADR 0017 启动诊断与系统授权证据

状态：Accepted

日期：2026-10-10

## 问题与边界

首次打开的等待可能发生在系统允许执行程序之前，也可能发生在应用初始化内部。应用日志无法记录尚未运行的代码，需要独立采集系统日志和进程状态。诊断能力不等于问题已修复，不保证系统内部原因能完全定位。

## 决策

应用使用 Unified Logging 的固定 subsystem `com.hongdazhu.SpaceJudge`、category `Startup`，按固定枚举记录 Swift 入口、生命周期、缓存准备、数据库连接、模型就绪、界面出现和退出。记录包含 UTC 时间、连续时钟经过毫秒、会话 UUID、递增序号、PID、版本与 build。阶段为 notice，失败为 error，避免依赖未持久化的 debug 日志；系统仍可能丢弃日志，记录缺失不是未执行的充分证据。

应用日志不记录路径、扫描结果、文件名、错误描述或任意 error domain。错误只保留白名单分类和数值码；版本字段必须为限定长度的数字版本格式。日志数量限于启动与生命周期，不按扫描节点输出，也不创建额外日志数据库。应用入口前发生的阻塞由独立工具判断。

独立 Ruby 脚本使用 macOS 系统工具，提供 snapshot 与 watch 两种模式。它采集签名验证、二进制校验和、隔离属性、系统启动时间、应用进程信息和采样，以及系统授权和启动日志。每项命令有时间与输出量限制，失败或权限不足必须写入 manifest，不能把空输出解释为没有问题。它不启动或终止应用、不重扫、不改权限、签名、隔离属性或系统安全策略，不自动上传。

诊断目录新建为 0700，文件为 0600，不能复用或覆盖已有目录。原始系统日志、签名与隔离元数据、进程采样可能包含用户路径、下载 URL 和其他应用的授权事件。这些属于私密原始证据，不承诺匿名化，不进入公开仓库，不直接附到 GitHub issue。

## 验证与限制

单元测试覆盖应用记录序号、时钟、字段限制与错误脱敏，脚本测试覆盖参数边界、权限、超时、输出限制和失败状态。构建证明启动埋点可编译，不证明首次下载授权可靠。真实复现必须在点击“仍要打开”前开启 watch，记录点击和锁屏解锁的时间，保留同一安装包和校验和。

首先只在隔离的开发缓存中验证应用日志，不替换正在使用的安装版本。遇到启动前阻塞时，不通过删除隔离属性、重新签名或更换程序来掩盖现场。
